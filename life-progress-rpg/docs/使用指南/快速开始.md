# 开发快速开始

> 文档名称：快速开始（使用指南）
> 更新时间：2026-09-27
> 适用于 v0.1 本地优先版本

## 环境要求

| 工具 | 要求 |
|------|------|
| Node.js | >= 20（见 `package.json` engines） |
| npm | 与 `package-lock.json` 兼容的版本 |
| 浏览器 | 支持 IndexedDB 的现代浏览器 |

## 启动

```bash
git clone <repository-url>
cd life-progress-rpg
npm install
npm run dev
```

`<repository-url>` 是占位符，发布文档前必须替换为真实地址。

也可使用后台守护脚本（写入 `logs/dev-server.log`，用 `./stop.sh` 停止）：

```bash
./start.sh [host] [port]
```

## 环境变量说明

**当前代码没有任何 `VITE_*` 环境变量开关**，本地模式就是默认且唯一可运行模式，`.env` 文件不需要创建：

- 数据保存在当前浏览器的 IndexedDB，无需数据库和密钥。
- AI 请求路径硬编码为同源 `/api/reflections`（`src/services/ai/reflection-service.ts`）。
- 该端点当前没有服务端实现，启用 AI 同意后的请求必然失败并回退到本地当日回应。

服务端代理实施后的目标配置约定（尚未生效，供实施时参考）：

- 浏览器端禁止出现 `VITE_AI_API_KEY` 或任何供应商密钥。
- 供应商密钥只配置在服务端运行环境，例如 `AI_PROVIDER_API_KEY`、`AI_PROVIDER_MODEL`（服务端变量）。
- 服务端变量不得以 `VITE_` 开头，不得提交到 Git，不得输出到日志。

## 启动后验证

1. 首次引导只要求出生年份，并可关闭进度展示。
2. 创建记录后刷新页面，数据仍然存在。
3. 断网后仍可创建、编辑和导出记录。
4. 默认规则复盘不发起网络请求。
5. 未同意 AI 时不发起任何 AI 请求。
6. 生产构建产物中搜索不到 API Key。

## 常用检查

以 `package.json` 中已有脚本为准：

```bash
npm run build
npm run lint
npm run test -- --run
npm run test:e2e
```

若脚本不存在，应先在项目中添加对应配置，而不是在文档中假定它存在。
