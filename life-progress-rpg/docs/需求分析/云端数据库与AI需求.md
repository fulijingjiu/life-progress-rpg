# 云端数据库与 AI 需求

更新时间：2026-08-21
状态：已立项，待实施
目标版本：v0.2 云端基础能力

## 1. 决策摘要

后续版本确定接入云端数据库和真实 AI 服务。当前 IndexedDB 不废弃，继续承担离线缓存和本地优先写入；云端负责账号、跨设备同步、备份与 AI 服务端代理。

最小上线形态：

```text
React + Dexie（本地优先）
        │
        ├── 认证、同步 ──> Supabase Auth + PostgreSQL + RLS
        │
        └── AI 请求 ────> 单个 Edge Function ──> AI Provider
```

首期不引入微服务、API Gateway、Redis、消息队列、向量数据库或自建模型。

## 2. 背景与问题

当前版本的数据只存在单个浏览器的 IndexedDB 中，具备隐私友好、离线可用和低部署成本等优点，但存在以下限制：

- 更换设备或清除浏览器数据后，用户无法自动恢复。
- 多设备编辑无法同步，也无法识别冲突。
- `/api/reflections` 只有客户端契约，没有真实服务端实现。
- AI 密钥不能安全放在浏览器中，必须由服务端代理。
- 云端导出、删除、备份恢复和访问控制尚未实现。

## 3. 产品目标

1. 用户登录后可以安全地在多台设备查看和编辑自己的设置与记录。
2. 断网时仍可记录，恢复网络后自动同步，不因 AI 或网络失败丢失内容。
3. 首次登录时可以把现有本地数据迁移到账号，并在覆盖前看见冲突。
4. AI 只在用户明确同意后处理必要字段，失败时始终保留本地回应。
5. 用户可以导出云端数据、撤回 AI 同意并删除账号及其云端数据。

## 4. 非目标

首期不包含：

- 社交、公开主页、排行榜或跨用户比较。
- 团队账号、组织权限和后台运营系统。
- AI 聊天、长期记忆、向量检索或自动人生规划。
- 医疗/心理诊断、寿命预测、重大决策建议。
- 实时协同编辑；同步达到最终一致即可。

## 5. 用户与核心流程

### 5.1 未登录用户

- 继续使用现有本地记录功能。
- 可以导入、导出和清空本地数据。
- 不能调用真实 AI，使用本地规则回应。
- 页面明确说明数据仅保存在本设备。

### 5.2 登录用户

- 通过邮箱验证码或 Magic Link 登录。
- 首次登录选择“上传本地数据”或“暂不上传”。
- 登录后本地保存立即成功，后台同步到云端。
- 新设备登录后下载自己的设置和记录。
- 可以查看同步状态、手动重试和处理冲突。

### 5.3 AI 启用流程

1. 展示发送字段、用途、供应商类别和保留策略。
2. 用户主动开启 AI。
3. 记录先写入本地并同步到云端。
4. 服务端根据记录 ID 读取当前用户自己的记录，调用 AI。
5. 合法回应写回云端并同步到本地；失败保留本地规则回应。

## 6. 功能需求

| 需求编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-CLOUD-001 | 邮箱无密码登录、退出和会话恢复 | P0 | 用户只能访问自己的数据；刷新后会话可恢复；失效会话回到本地模式 |
| R-CLOUD-002 | 本地数据首次迁移 | P0 | 上传前显示设置数、记录数和冲突数；取消不改动两端数据 |
| R-CLOUD-003 | 设置与记录云端同步 | P0 | 新增、编辑、删除可跨两台设备最终一致；每用户每天仍只有一条记录 |
| R-CLOUD-004 | 离线写入与自动重试 | P0 | 断网保存成功并标记待同步；联网后自动补传；失败可手动重试 |
| R-CLOUD-005 | 同步冲突处理 | P0 | 同一记录两端均修改时不静默覆盖；用户可以选择本地版或云端版 |
| R-CLOUD-006 | 同步状态展示 | P1 | 设置页显示已同步、待同步、失败或冲突，不使用阻塞式全屏状态 |
| R-CLOUD-007 | 云端导出与账号删除 | P0 | 导出包含当前账号全部业务数据；删除需再次确认并使会话失效 |
| R-AI-001 | 真实 AI 服务端代理 | P0 | 浏览器中不存在供应商密钥；请求经过鉴权、限流和结构校验 |
| R-AI-002 | AI 明示同意与撤回 | P0 | 默认关闭；关闭后不再发起新请求；本地核心功能不降级 |
| R-AI-003 | 最小数据发送 | P0 | 当日回应只发送当前记录的心情、能量、标签和备注，不发送历史或出生年份 |
| R-AI-004 | AI 输出安全校验 | P0 | 超长、格式错误、事实不一致或高风险输出不得替换本地回应 |
| R-AI-005 | AI 失败回退 | P0 | 超时、限流、供应商故障或离线时记录仍保存，显示本地回应 |
| R-AI-006 | 用量与成本控制 | P0 | 每用户有日额度；重复请求幂等；服务端记录不含正文的用量指标 |
| R-AI-007 | AI 质量反馈 | P1 | 三类反馈同步到云端；未同意匿名分析时不进入聚合分析 |

## 7. 数据与同步规则

### 7.1 数据所有权

- 认证系统生成的用户 UUID 是云端所有权主键。
- 浏览器不得提交任意 `userId` 代表他人；服务端从登录会话取得用户 ID。
- PostgreSQL 对所有业务表启用 Row Level Security，只允许用户访问自己的行。
- 当前 `local-user` 仅作为未登录状态的本地标识，不能直接作为云端用户 ID。

### 7.2 本地优先

- 用户点击保存后先提交 IndexedDB 事务，再进入同步队列。
- 同步失败不回滚本地记录。
- IndexedDB 增加同步队列、同步游标、版本和删除墓碑。
- 服务端返回版本号；客户端只在基准版本一致时覆盖记录。

### 7.3 冲突

- 设置项首期采用服务端最后写入版本，并记录更新时间。
- 日记正文发生并发冲突时不得自动覆盖，客户端保留两份候选并要求用户选择。
- 删除也参与版本比较；删除墓碑保留一段恢复窗口后再物理清理。
- 首次迁移遇到同一日期两条记录时逐条合并，不以导入顺序决定。

## 8. AI 产品规则

- AI 是文字整理层，不负责计算统计、趋势、相关性或人生结论。
- 输入记录视为不可信数据，不能覆盖服务端系统提示。
- 模型、系统提示、供应商密钥和配额只配置在服务端。
- 输出通常为 30～70 个中文字符，最多 90 个字符和两句话。
- 禁止诊断、因果推断、预测、人格判断、操控式建议和虚构事实。
- 用户标记“事实不准确”后保留反馈类型，不记录原始正文到日志。
- AI 供应商或 Prompt 变更必须重新运行固定评测集。

## 9. 安全与隐私要求

| 范围 | 最低要求 |
| --- | --- |
| 传输 | 生产环境仅 HTTPS；限制允许的来源 |
| 鉴权 | 短期访问令牌、可撤销会话；敏感操作重新确认 |
| 授权 | 业务表启用 RLS；数据库策略按 `auth.uid()` 限制所有者 |
| 密钥 | AI 密钥和数据库高权限密钥只存在服务端环境变量 |
| 日志 | 不记录备注正文、昵称、出生年份、完整 Prompt 或完整 AI 回复 |
| 限流 | 按用户和来源限制登录、同步与 AI 请求 |
| 数据权利 | 支持导出、删除账号、撤回 AI 同意和清除本地副本 |
| 备份 | 定义备份频率、恢复演练和删除传播期限 |

上线前必须补充隐私说明：处理目的、数据字段、供应商、地区、保留期限、删除时限和联系方式。

## 10. 非功能需求

| 指标 | 首期目标 |
| --- | --- |
| 本地保存 | 不等待网络或 AI；保持当前交互速度 |
| 同步可靠性 | 可重试、幂等，不产生同日重复记录 |
| API 可用性 | AI 故障不影响记录；同步故障有状态和恢复入口 |
| AI 延迟 | 超过前端超时阈值即回退，不持续阻塞页面 |
| 数据隔离 | 自动化验证用户 A 无法读取或修改用户 B 的数据 |
| 可恢复性 | 迁移、冲突和删除流程均有可重复测试 |

## 11. 分阶段交付

### 阶段 C1：账号与只读云端基础

- 创建 Auth、PostgreSQL 表、约束、迁移和 RLS 策略。
- 增加登录、退出、会话恢复。
- 新设备可以下载云端数据到空的本地数据库。

### 阶段 C2：双向同步

- 增加本地同步队列、版本、墓碑和游标。
- 完成本地首次迁移、增删改同步、重试和冲突界面。
- 完成跨设备 Playwright 流程、RLS 隔离测试和恢复演练。

### 阶段 C3：真实 AI

- 实现一个鉴权的 AI Edge Function。
- 接入固定 Prompt、输入输出校验、限流、幂等、成本指标和本地回退。
- 使用固定评测集验证事实一致性与高风险边界。

### 阶段 C4：数据权利与发布

- 云端导出、账号删除、撤回同意、隐私说明和备份恢复。
- 完成安全检查、性能检查、费用上限和生产监控。

## 12. 发布完成定义

只有以下条件全部满足，云端与 AI 才能标记为“已实现”：

- 数据库迁移可从空库重复执行，RLS 隔离自动化通过。
- 本地首次迁移、跨设备增删改、断网恢复和冲突处理通过。
- AI 密钥不进入前端构建产物，AI 请求必须有合法会话。
- AI 正常、超时、限流、非法输出和供应商故障场景全部回退正确。
- 用户可以导出数据、撤回同意并删除账号。
- 文档、隐私说明、部署变量和故障恢复步骤与生产行为一致。
